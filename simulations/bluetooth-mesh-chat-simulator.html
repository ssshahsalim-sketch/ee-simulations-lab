Why you can't just "chat over Bluetooth" past a wall

A normal Bluetooth link is point-to-point (or one master with a handful of slaves), with a practical range of roughly 10–30 m for the Class 2 radios in phones. If the person you want to reach is beyond that, there's no direct radio path — the fix isn't a stronger radio, it's letting every phone in between act as a relay so the message hops from device to device until it arrives.

Managed flooding, in short

1 · SEND
You broadcast the message to whoever is in range
→
2 · RELAY
Each device that hears it re-broadcasts once
→
3 · DEDUPE
Devices cache message IDs so they don't repeat forever
→
4 · TTL
A hop-count limit (e.g. 6–8) stops it spreading endlessly
→
5 · ARRIVE
Recipient's device sees its own ID and keeps the message

This is exactly the model the official Bluetooth Mesh profile (a Bluetooth SIG standard, separate from ordinary point-to-point Classic/BLE) uses for things like mesh light-bulb networks — and it's the same principle mesh chat apps repurpose for people instead of light switches.

What happens when nobody is in range yet

  • Real mesh chat apps use store-and-forward: if no route exists right now, your phone holds the message and keeps trying as new devices come into range.
  • As soon as any relay device moves into range of both you and the recipient (or another relay closer to them), the message continues its hop toward the destination.
  • This means the "reachable" set of the chat isn't fixed — it grows and shrinks live as people physically move, which is exactly what the simulator on the next tab lets you drag around and watch happen.

Why this can't be a "real" working app inside a browser

Everything above needs a native app because it depends on radio capabilities a web page simply isn't given:

  • Web Bluetooth is GATT-client-only — a browser tab can connect to a known accessory, but it can't advertise itself as a discoverable peripheral or run a background relay service the way a phone OS can.
  • No background scanning — the browser can't continuously listen for nearby devices the way a mesh relay needs to.
  • iOS Safari doesn't support Web Bluetooth at all, so even the limited client-only access isn't available on iPhone.

The simulator on the next tab reproduces the network behaviour faithfully — real range limits, real multi-hop routing, real "no path yet" queuing — using simulated positions and radios, so you can see exactly how the hopping decision is made before building or choosing a native app like the ones above.
