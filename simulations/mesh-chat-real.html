Why this uses Wi-Fi instead of literal Bluetooth (read before connecting)

A web page cannot access your phone or laptop's Bluetooth radio the way a native app can — browsers only allow connecting to a known Bluetooth accessory (like headphones), never advertising themselves as discoverable or relaying data in the background. That's a fixed security boundary in every browser, including on iOS where Web Bluetooth isn't available at all.

What is real here: this app uses RTCPeerConnection data channels — a genuine live network link between devices, usually over the same Wi-Fi. The mesh behaviour itself — flooding a message to every connected device, each one relaying it exactly once, a hop-limit so it doesn't circulate forever, duplicate detection so nobody sees the same message twice — is implemented the same way Bitchat's actual protocol works. It's just riding on Wi-Fi instead of Bluetooth's radio.
